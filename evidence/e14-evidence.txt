Read inventory.service.ts's submitStockEntry() - the primary path

  const invItem = await tx.inventoryItem.upsert({
    where: { tenantId_productId_warehouseId: {...} },

No prior read of current quantity, no floor, no policy check of any
kind - a bare Prisma decrement.

THE BUG, CONFIRMED
====================
A stock entry requesting 50 units from a warehouse with only 20 units
on hand was submitted via submitStockEntry(). The pre-existing code
resolved successfully with no rejection, decrementing straight through
to a negative on-hand balance (-30).

MECHANISM (this phase's own fix)
====================================
submitStockEntry()'s fromWarehouseId branch now reads the current
on-hand quantity via tx.inventoryItem.findFirst() inside the same
transaction, immediately before the decrement, and throws
BadRequestException (naming the product, warehouse, available
quantity, and requested quantity) if the requested quantity exceeds
what's available.
