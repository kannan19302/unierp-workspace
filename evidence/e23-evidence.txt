THE CONSENT INVESTIGATION
============================
A21's own exit criterion: "a per-user preference suppresses delivery
across all 45 modules... no module sends mail directly."

  $ grep -rl "communicationOptOut" unierp-api/src
  (zero results)

The schema already has a generic, entity-agnostic
CommunicationOptOut model (entityType/entityId/channel — the exact
same shape as ApprovalRequest, SalesDocumentTemplate, and
saved-views' own generic tables this session has repeatedly found and
reused), but nothing in the codebase ever queries it.
CrmCampaignManagementService.buildAudience() — the method deciding
who a marketing campaign targets — included every matching lead,
contact, and customer with zero consent check. Filed as D072
(CRITICAL) — this is a regulatory-compliance gap (CAN-SPAM/GDPR/PECR),
not just a UX one.

MECHANISM (this phase's own work)
====================================
New private excludeOptedOut(tenantId, entityType, records) on
CrmCampaignManagementService: queries CommunicationOptOut for the
EMAIL channel against the candidate record ids, and filters out any
match. Called from buildAudience() for all three entity types
(LEAD/CONTACT/CUSTOMER) before any count or sample is computed —
filtering happens BEFORE sampling, so a "top 10" result can never
happen to include opted-out rows that a naive filter-after-sample
would miss.

WHAT THIS PHASE DOES NOT COVER
=================================
Filed D072 (CRITICAL) with three explicit follow-ups:
1. Only the EMAIL channel is checked — CommunicationOptOut.channel is
   free-text, so SMS/other-channel opt-outs are not yet consulted.
2. Whether the SAME gap exists in other modules that send bulk
   communication (notifications, communication) was not swept
   platform-wide — this is the SECOND finding this session (after
   D070/A25) of a platform-wide compliance claim (A21's "no module
   sends mail directly") with no verified supporting mechanism. A
   dedicated cross-module audit is a high-priority follow-up, stated
   not silently assumed resolved by this one fix.
3. excludeOptedOut() now fetches the full matching record set rather
   than a database-level take:10, since filtering must happen before
   sampling for correctness. Acceptable for this fix's
   correctness-first scope; a `NOT IN` at the database layer would
   avoid the full-fetch for very large audiences, noted as future
   perf work.
