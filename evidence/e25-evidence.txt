THE INVESTIGATION
==================
Found evaluateTicketSla(tenantId, ticketId) in field-service-tickets.

slaBreached: true. Searched for all callers:

  $ grep -rn "evaluateTicketSla" src/modules/field-service/*.ts

No cron/scheduled job found. Read closeTicket() in full - it updates
status to CLOSED, sets completedDate, resolution, costs - and never
touches slaBreached at all.

THE BUG, CONFIRMED
====================
A ticket with slaDeadline one hour in the past, closed via
closeTicket(), was marked CLOSED with slaBreached never set (absent
from the update() call entirely) - identical to how an on-time ticket
would be closed. Every SLA-compliance report/stat in this module reads
this same field, so this silently inflates reported SLA compliance for
any ticket resolved through the normal close flow.

MECHANISM (this phase's own fix)
====================================
closeTicket() now computes slaBreached (comparing the actual
completion time against slaDeadline, or preserving any prior true
value) and includes it in the same update that sets status: "CLOSED" -
SLA compliance is evaluated at the one guaranteed trigger point every
ticket passes through.
