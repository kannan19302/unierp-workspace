THE QUOTA INVESTIGATION
==========================
StorageQuota.storageLimit (BigInt, 1GB default, settable via
updateQuota()) was never read by registerFile() — the only place
uploads are recorded. Confirmed by reading storage.service.ts
end-to-end: registerFile() created the file row, then called
ensureQuota() (which only creates a MISSING quota row, not a limit
check) and incremented storageUsed unconditionally. No refusal path
existed anywhere.

MECHANISM (this phase's own work)
====================================
registerFile() now:
  1. Ensures a quota row exists (ensureQuota(), unchanged).
  2. Fetches it and checks `storageUsed + BigInt(dto.size) >
     storageLimit`.
  3. Refuses (BadRequestException, naming used/requested/limit byte
     counts) BEFORE creating the file row if the upload would exceed
     the limit.
Removed the now-redundant second ensureQuota() call that previously
sat after file creation (quota is now established up front, once).
