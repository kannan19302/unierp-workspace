E34 — Standard report library
Deliverable: "The reports each module is expected to have -
statutory, operational, management - as governed definitions."
Exit: "Every module's expected report set exists and reconciles to
its source data."

SCOPE NOTE
==========
Investigated "reconciles to its source data" directly by auditing the
three core financial statements (balance sheet, P&L, trial balance) -
the most statutorily significant reports named implicitly by this
phase - and found all three shared the identical, severe defect:
none of them filtered journal entries by their parent Journal's
status, silently including unposted DRAFT entries as if they were
real, finalized transactions. Fixed all three, proved each via
break/restore, and files the honest remaining scope (this same
pattern was not checked across the rest of the codebase's many other
reporting methods).

THE INVESTIGATION
==================
Read getBalanceSheet() in full: queries journalEntry.findMany() with
tenantId/createdAt/account.type filters but NO filter on the parent
Journal's status field. Journal.status defaults to "DRAFT", only
becomes "POSTED" once finalized (confirmed in the schema, same field
D084 fixed exactness-checking for earlier this session). Checked the
two sibling report methods in the same file - getProfitLoss() and
getTrialBalance() - and found the IDENTICAL gap independently present
in both.

THE BUG, CONFIRMED
====================
One real $100 POSTED journal entry and one $9,000 DRAFT entry against
the same asset account. getBalanceSheet() reported assets.total: 9100
instead of the correct 100 - a ~91x inflation entirely attributable
to an unposted, unapproved entry. The same pattern (with the same
magnitude) was independently confirmed in getProfitLoss()
(totalRevenue) and getTrialBalance() (totalDebits).

MECHANISM (this phase's own fix)
====================================
All three methods now add journal: { status: "POSTED" } to their
journalEntry.findMany() where-clauses - reports now only ever
reflect finalized, approved accounting facts.

PROOF
=====
$ npx vitest run src/modules/finance/tests/finance-operations.service.spec.ts

3 new tests (one per report method), each seeding one real POSTED
entry alongside one DRAFT entry with a much larger amount:
  - getBalanceSheet: asserts assets.total excludes the draft amount
  - getProfitLoss: asserts totalRevenue excludes the draft amount
  - getTrialBalance: asserts totals.totalDebits excludes the draft
    amount

All 3 FAILED against the pre-existing code before the fix - each
confirmed the draft entry's amount was included in the reported
total. Real FAIL-first proof, reproduced independently for all three
methods.
All 3 PASS after the fix. 50/50 tests in the file pass (47
pre-existing + 3 new).
