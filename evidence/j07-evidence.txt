new axe violation fails CI. Zero violations across the component

MECHANISM (this phase's own work)
====================================
1. Added a real vitest-axe assertion to modal.test.tsx:
     it("has no axe violations when open", async () => {
       const { container } = render(<Modal open .../>);
       expect(await axe(container)).toHaveNoViolations();
     });

2. Added 4 real vitest-axe assertions to stage-b1.test.tsx, covering
   Alert, Switch, RadioGroup, and PageHeader.

3. The Switch assertion FAILED on first run against real, unmodified
   component code:
     "ARIA toggle fields must have an accessible name
     (aria-toggle-field-name)"
   `Switch` (unierp-design-system/src/components/extended-inputs.tsx)
   rendered `<div role="switch">` wrapped in a `<label>`, but wrapping
   a non-native ARIA widget in a <label> does not give it an
   accessible name per the ARIA spec — axe correctly flagged it as a
   genuine violation, not a false positive.

4. Fixed the real component: gave the switch div an `id`, added
   `aria-labelledby` pointing at a new `<span id={labelId}>{label}</span>`
   wrapping the label text. Re-ran — passes.

CRITICAL FINDING — B23's gate is fabricated (filed as D063)
===============================================================
`unierp-workspace/scripts/ci/check-axe-a11y.mjs` (B23's claimed
deliverable) does not run axe-core, does not invoke any test runner,
and does not read any real test output. It only checks that
`WCAG_CONFORMANCE.md` exists and contains a literal string, then
unconditionally writes a hardcoded
`{ testedComponents: 25, axeViolationsCount: 0, status: "PASSED" }`
baseline file and exits 0 — regardless of whether any component was
ever tested. It cannot fail no matter how many real axe violations
exist. `WCAG_CONFORMANCE.md` itself makes a false claim ("Zero
axe-core accessibility violations are enforced via automated CI
testing on every pull request") that this gate does not back up.
Filed in full detail as D063 in 90-DEFECT-LOG.md. This phase does NOT
rely on or extend the fabricated gate; it reports the real, measured
state above instead.

WHAT THIS PHASE DOES NOT COVER
=================================
Full "zero violations across the component library and all routes" is
a large, multi-session effort: ~17-21 component files need dedicated
axe assertions, and unierp-web/unierp-console need axe test
infrastructure built from scratch (currently none exists). Per this
session's D12/D19/J04 precedent, fabricating shallow coverage to claim
completeness would be worse than this honest, measured report. B23
itself needs to be reopened and its gate rewritten to actually invoke
the test runner rather than hardcode a pass.
