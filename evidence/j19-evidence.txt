THE INVESTIGATION
==================
Read docs/ai/APP_FLOW.md (unierp-workspace) and extracted its 7
documented journeys: A (Onboarding), B (Daily sign-in), C (The
universal record lifecycle), D (Approval workflow), E (Frontline
mobile), F (AI Copilot), G (Extending without forking).

Read all 11 existing e2e/journeys/*.spec.ts files in unierp-web and
found NONE of them corresponded by name or intent to journeys A, B,
D, E, or F - the existing suite covers module-specific CRUD flows
(order-to-cash, procure-to-pay, manufacturing, supply-chain,
projects, communication, gl-post-close - real instances of Journey
C's generic pattern) and three cross-cutting security/lifecycle
concerns (tenant-isolation, plane-2-boundary, user-lifecycle - real
tests of APP_FLOW.md section 11 rules, not named journeys). Only
builder.spec.ts ("create and verify a custom entity") was a genuine,
direct match for a named journey (G).

THE GAP, CONFIRMED
====================
5 of 7 documented journeys (A, B, D, E, F) had zero dedicated E2E
coverage, and 10 real, existing spec files had never been connected
back to the journey list they should be proving - exactly the two
halves of this phase's own exit criterion, both genuinely unmet.

MECHANISM (this phase's build)
====================================
Added scripts/check-e2e-journey-coverage.mjs: parses APP_FLOW.md's
journey headings directly from the doc (the single source of truth)
and checks a committed manifest (e2e/journey-coverage.json) mapping
each journey to real spec files. Fails if a journey has no mapped
spec, a mapped spec doesn't exist, or a real spec file is referenced
by nothing. Journeys that test a cross-cutting behavioural rule
(APP_FLOW.md section 11) rather than one of the 7 named journeys are
explicitly allowlisted (crossCuttingSpecs) with a stated reason,
rather than force-mapped to an incorrect journey or silently
ignored. Journey E (frontline mobile) is marked explicitly
outOfScope for this WEB Playwright suite, with a stated reason
(needs its own coverage in unierp-mobile) - not silently skipped.

Added a real new spec, e2e/journeys/daily-sign-in.spec.ts, covering
Journey B's plain email/password success and 401 (no-account-
disclosure) outcomes - the documented behavior APP_FLOW.md section 5
names explicitly ("never reveal which [field is wrong]"). This
reduced the real coverage gap from 5 journeys to 3.
