K04 — Evidence collection automation
Deliverable: "Automated evidence: access reviews, change management,
audit logs, vulnerability management, backup verification -
generated continuously rather than assembled before an audit."
Exit: "An auditor's evidence request is satisfiable from generated
artefacts. Nothing is assembled by hand the week before."

THE INVESTIGATION
==================
Read ComplianceController (src/modules/saas/compliance.controller.ts),
the API surface most directly named by this phase's own deliverable
("evidence... satisfiable from generated artefacts"). Found systemic
fabrication across nearly every read endpoint - the same defect class
K03 (D118) already found and removed from the PUBLIC marketing site,
here reproduced server-side through an AUTHENTICATED API, presented as
if it were real compliance evidence:

  - listCertifications(): hardcoded `{standard: "SOC 2 Type II",
    status: "certified", certifiedAt: "2024-01-01", expiresAt:
    "2025-01-01"}` and `{standard: "GDPR", status: "compliant"}` -
    identical for every tenant, regardless of reality. This platform
    holds no third-party certification of any kind (confirmed by
    K03's own investigation this session).
  - listComplianceStandards(): claimed SOC 2 "certified".
  - getHipaaStatus(): claimed `compliant: true, controls: 120,
    passed: 118` - a fully fabricated control-count with no HIPAA
    program, no BAA process, no PHI-specific controls anywhere in
    this codebase (also confirmed by K03).
  - getGdprStatus(): claimed hardcoded `dataExports: 3,
    erasureRequests: 1` for every tenant, regardless of how many real
    export/erasure requests that tenant actually has - even though
    the real underlying models (DataExportJob, DataErasureRequest)
    exist and are queryable.

An auditor pointed at this API today would receive confident,
specific, false claims - the polar opposite of "generated
continuously" evidence; it was static fiction served through a live
endpoint.

MECHANISM (this phase's fix)
====================================
Fixed four endpoints to return the real, honest state instead:
  - listCertifications(): every standard now `not_certified`, matching
    K03's own scope decision (SOC 2/ISO 27001 out of scope, no dated
    target).
  - listComplianceStandards(): SOC 2/HIPAA no longer claimed
    certified/in_progress-as-if-real.
  - getHipaaStatus(): compliant: false, controls: 0, passed: 0 -
    honestly reflecting that no HIPAA program exists.
  - getGdprStatus(): dataExports/erasureRequests are now REAL,
    tenant-scoped Prisma counts (prisma.dataExportJob.count /
    prisma.dataErasureRequest.count), not hardcoded numbers.

WHAT THIS PHASE DOES NOT COVER — the honest, load-bearing gap
===================================================================
Filed as D125 (CRITICAL). Not fixed in this pass:
  - listComplianceReports()/getComplianceReport()/
    runComplianceScan() are ALSO fabricated (hardcoded "status:
    compliant", fake findings: [], fake generatedAt dates) but were
    not fixed - these are more of a "generated document" workflow
    (report generation, scanning) than a direct certification claim,
    a larger, separate build (an actual report-generation pipeline)
    out of this pass's tractable scope.
  - The deliverable's five named evidence categories - "access
    reviews, change management, audit logs, vulnerability management,
    backup verification" - were not built as a coherent automated
    pipeline. Audit logs already have a real source (C03, this
    session's own J25 built a real backup-verification rehearsal
    mechanism, though not yet wired live) but access reviews, change
    management, and vulnerability management have no automated
    evidence generation anywhere in this codebase, confirmed by grep
    - not investigated in depth in this pass.
  - This fix stops the API from LYING; it does not yet make the
    evidence "generated continuously" in the sense of an actual,
    running evidence-collection pipeline an auditor could point to.
