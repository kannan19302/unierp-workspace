BUDGET — stated and justified, not arbitrary
=================================================
A token-exact budget was worked out first and rejected as
impractical: 150,000 tokens (a commonly-cited practical working
budget for a coding agent, leaving room for the conversation itself)
divided by ~3.5 characters/token and ~45 characters/line gives ~950
lines even at the full 150K figure, or ~380 lines at a more realistic
40%-of-window per-task allocation — either would flag nearly every
one of the 46 real modules, producing a universally-failing, useless
signal rather than a meaningful one. A deliberately generous
LINE-based budget of 10,000 lines was used instead — large but still
single-sitting-readable — so PASS/FAIL carries real information. This
reasoning is stated explicitly in the script's own header comment,
not hidden as if the number were self-evidently correct.

MECHANISM
=========
For each of the 46 real module directories under
unierp-api/src/modules, sums total lines across every .ts file
(module code + its own *.spec.ts tests, per the deliverable's own
"module code ... and its tests"). Schema-slice and cross-repo-contract
portions were NOT measured — stated explicitly as a real limitation
(see below), not hidden.

WHAT THIS PHASE DOES NOT COVER — the honest, load-bearing gap
===================================================================
Filed as part of D082:
1. The schema-slice and contracts portions of "must load" were not
   measured — core.prisma (31,092 lines) has no reliable per-module
   boundary to extract mechanically, and unierp-contracts has no
   per-module directory structure. This means the true per-module
   "must load" size is LARGER than what this measurement reports for
   every module, not smaller — a floor, not a ceiling.
2. 16 of 46 modules exceeding the stated budget were NOT fixed in
   this pass — per the exit criterion's own words, this is
   L07-L09's decomposition work (one file each already proven, the
   rest filed as D077/D078/D079), not a new effort this phase should
   duplicate.
