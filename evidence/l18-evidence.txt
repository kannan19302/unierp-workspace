MECHANISM
=========
New scripts/generate-architecture-maps.mjs generates 4 real maps into
docs/architecture/, all purely from static analysis — no hand-written
content, matching L17's own drift-proof pattern (--check regenerates
in memory and diffs against the committed file):

  1. module-dependency-graph.md — every real `from "../other-module/"`
     relative import within unierp-api/src/modules.
  2. event-flow.md — every `.emit("literal")` call matched against
     every `@OnEvent("literal")` listener, cross-module.
  3. permission-matrix.md — every module's `@Permissions("literal")`
     strings, one consolidated table (same real per-module data L17
     already computes, presented cross-module here).
  4. repo-layer-graph.md — every repo's own package.json dependencies
     filtered to @kannan19302/* packages — the real declared
     repo-to-repo graph, not asserted from memory.

REAL RESULT — genuine architectural findings, not decoration
==================================================================
$ node scripts/generate-architecture-maps.mjs
Wrote 4 architecture map(s).

Module dependency graph: 4 real cross-module import edges across 46
modules. 3 are the CORRECT pattern (blockchain/ecommerce/sales all
import the shared `outbox` module directly, as expected). 1 is not:
`advanced-finance` imports directly from `finance` — one business
module reaching into another's files, bypassing the outbox/event
pattern this platform requires. Filed as part of D083.

Event flow: 80 distinct event names found; 63 (79%) have zero
listeners found anywhere in unierp-api/src/modules. Not automatically
dead code (a listener could live outside this scan's scope), but a
real, notable ratio worth triaging — filed as part of D083.

Repo layer graph: 21 real repos with a package.json, each with its
actual declared @kannan19302/* dependencies (e.g. unierp-api depends
on 8 shared packages; unierp-console depends on 3).
